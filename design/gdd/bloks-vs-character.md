# BLOKS vs CHARACTER — Game Design Document

**Версия:** 1.0 | **Дата:** 2026-03-25 | **Движок:** Unity 2D + Photon PUN2
**Статус:** Draft | **Платформы:** PC (Windows), WebGL

---

## 1. Overview

BLOKS vs CHARACTER — асимметричный мультиплеер 1v1 для двух игроков (локально или онлайн через Photon PUN2). Один игрок (P1-Bloks) управляет классическим тетрисом: перетаскивает фигуры-тетромино на поле и заполняет пространство. Второй игрок (P2-Character) управляет персонажем-платформером, который находится внутри активного поля тетриса и пытается выбраться через Exit. Игроки преследуют взаимно противоположные цели: P1 хочет раздавить или заблокировать персонажа, P2 хочет выжить и добраться до выхода. Матч длится 3 минуты. Если за это время P2 не достиг Exit и не погиб — победа по умолчанию присваивается P1. Третий элемент — BombNPC — специальная "фигура" в очереди P1, которая после приземления превращается в автономного врага, преследующего персонажа.

## 2. Player Fantasy (что чувствует каждый игрок)

### P1 — Bloks

**Целевое ощущение:** стратегическое господство, контроль пространства, давление.

P1 — архитектор-тюремщик. Он видит поле целиком, методично перекрывает пути персонажа, выбирает момент для выброса BombNPC. Пиковый момент: персонаж зажат блоками без выхода. Фигуры падают быстро — есть постоянное тактическое давление, нельзя играть бесконечно медленно.

**Целевые MDA-aesthetics:** Challenge (тактическое планирование), Expression (выбор куда класть фигуры), Fantasy (роль надзирателя).

### P2 — Character

**Целевое ощущение:** выживание под давлением, ловкость, смекалка, побег.

P2 — заключённый в рушащемся здании. Каждый прыжок имеет ставку. Wall jump в щель между блоками, уничтожение блока в последнюю секунду, толчок BombNPC обратно в стопку — целевые пики мастерства. P2 слабее, но не беспомощен: три активные способности дают инструменты активного сопротивления.

**Целевые MDA-aesthetics:** Challenge (реакция, чтение поля), Sensation (juicy feedback прыжков и разрушений), Fantasy (роль беглеца).

## 3. Core Loop (основной игровой цикл)

### Micro-loop (0–30 секунд)

**P1:** взять следующую фигуру из превью (drag), опционально повернуть (W), бросить на сетку в нужную колонку (drop). Наблюдать ghost-превью. Фигура падает автоматически.

**P2:** читать поле, двигаться влево/вправо, прыгать, реагировать на падающие блоки. Управлять кулдаунами способностей (X, Z, Numpad0).

### Meso-loop (1–3 минуты)

Блоки накапливаются — поле сужается. P2 ищет маршрут к Exit, P1 перекрывает его. Переломный момент — BombNPC: после приземления P2 вынужден либо уничтожить NPC способностями, либо убегать — это ограничивает маршрут к Exit. Динамика меняется каждые 30–60 секунд по мере роста поля.

### Macro-loop (одна сессия)

Матч заканчивается одним из четырёх событий: персонаж достигает Exit (победа P2), персонаж умирает от блоков/BombNPC/ямы (победа P1), истекает таймер 3 минуты (победа P1). После победы — экран результата, кнопка Restart.

**Петли подкрепления (reinforcing loops):**
- Блоки накапливаются → поле сужается → P2 получает меньше пространства → вероятность победы P1 растёт.
- P2 уничтожает блоки → появляются дыры → P1 вынужден закрывать их → темп падения фигур не успевает за целью P1.

**Балансирующие петли (balancing loops):**
- BombNPC взрывается → удаляет блоки в радиусе 3 клетки → временно облегчает поле для P2.
- Более заполненное поле → больше зазоров для wall slide → P2 получает больше вертикальной мобильности.

## 4. Mechanics — P1 Bloks (детальные правила)

### 4.1 Поле (Board)

- Сетка: **10 x 20 клеток** (стандарт Tetris Guideline).
- Координаты: x ∈ [0, 9] (лево → право), y ∈ [0, 19] (низ → верх).
- Клетка [x, y] может быть: пустой (`null`) или занятой (ссылка на Block).
- Система координат: `Board.transform` является корневой. Мировая позиция клетки = `Board.transform.TransformPoint(new Vector3(x, y, 0))`.

### 4.2 Тетромино (Tetromino)

Семь стандартных типов + один специальный:

| Тип  | Цвет    | HEX     | Форма (offsets от pivot)                           |
|------|---------|---------|---------------------------------------------------|
| I    | Cyan    | #00F0F0 | (-1,0) (0,0) (1,0) (2,0)                         |
| O    | Yellow  | #F0F000 | (0,0) (1,0) (0,1) (1,1)                          |
| T    | Purple  | #A000F0 | (-1,0) (0,0) (1,0) (0,1)                         |
| S    | Green   | #00F000 | (-1,0) (0,0) (0,1) (1,1)                         |
| Z    | Red     | #F00000 | (0,0) (1,0) (-1,1) (0,1)                         |
| J    | Blue    | #0000F0 | (-1,0) (0,0) (1,0) (-1,1)                        |
| L    | Orange  | #F0A000 | (-1,0) (0,0) (1,0) (1,1)                         |
| Bomb | Bright Red | #FF1A1A | (0,0) (-1,0) (1,0) (0,1) — особый, см. раздел 9 |

Тип Bomb не входит в обычную очередь тетромино. Он появляется как отдельный слот в превью и спаунится через отдельный механизм (см. раздел 9).

### 4.3 Drag & Drop

1. Следующая фигура отображается в панели NextPiecePreview (4 UI-ячейки).
2. P1 зажимает ЛКМ над панелью → начало drag. UI-ячейки скрываются.
3. Пока курсор над Board → показывается ghost piece в сетке (цвет 75% яркости, alpha 0.6). Фигура клампится по X: `gridX ∈ [-minOffsetX, Width - 1 - maxOffsetX]`.
4. Во время drag: клавиша W → поворот фигуры на 90° по часовой стрелке. Формула поворота: `(x, y) → (y, -x)`. Тип O не вращается.
5. Отпускание ЛКМ над Board → `TetrisController.SpawnAtColumn(gridX, rotatedOffsets)`.
6. Если `_current != null` (фигура уже активна) — новый спавн игнорируется. P1 должен ждать Lock.

### 4.4 Автоматическое падение

- Скорость: `_fallSpeed = 5` клеток/сек (по умолчанию).
- Механизм: аккумулятор `_fallAccum += _fallSpeed * Time.deltaTime`. Когда `_fallAccum >= 1` → попытка сдвинуть вниз на 1 клетку, `_fallAccum -= 1`.
- При невозможности сдвинуться вниз → **Lock** (фиксация).

**Нет ускорения с уровнем в текущей реализации.** `_fallSpeed` — единственный регулятор темпа (tuning knob).

### 4.5 Ghost Piece

- Отображает позицию, куда упадёт текущая фигура.
- Вычисляется: drop = максимальное количество клеток вниз, при котором позиции остаются валидными.
- Если drop == 0 → ghost не показывается.
- Ghost blocks не имеют коллайдеров (отключены при создании).

### 4.6 Фиксация (Lock) и очистка линий

1. Позиции фигуры записываются в `Board._grid`.
2. Камера шейкается: 0.08 сек, амплитуда 0.15.
3. Выполняется `ClearLines()`:
   - Проверяется каждая строка y от 0 до 19.
   - Если все 10 клеток строки заняты → строка очищается (блоки уничтожаются), все строки выше сдвигаются вниз на 1.
   - Камера шейкается: 0.3 сек, амплитуда 0.5.
   - Проверка продолжается с той же строки (чтобы не пропустить каскадную очистку).
4. Выполняется `ApplyGravity()`: для каждой колонки x — блоки уплотняются вниз без зазоров.
5. Спаунится следующая фигура.

### 4.7 Push Block (толчок блока)

P2 может толкнуть одиночный блок на 1 клетку горизонтально (способность Push, см. раздел 6). P1 не управляет этим — это сторона P2.

После Push: если целевая клетка свободна → блок перемещается с анимацией (0.1 сек DOTween), коллайдер временно отключён во время движения, затем вызывается `ClearLines()` и `ApplyGravity()`.

## 5. Mechanics — P2 Character (детальные правила)

### 5.1 Движение

| Действие   | Клавиши                | Значение         |
|------------|------------------------|------------------|
| Бег влево  | A / ←                  | `_moveSpeed = 5f` |
| Бег вправо | D / →                  | `_moveSpeed = 5f` |
| Прыжок     | W / ↑ / Space          | `_jumpForce = 12f` |
| Wall Jump  | W / ↑ / Space у стены  | сила (8f, 12f)   |

**Горизонтальное движение:** `rb.velocity.x = h * _moveSpeed`. Движение мгновенно (нет ускорения/инерции). При `h != 0` — спрайт отражается по X.

### 5.2 Прыжок

**Условие:** `_isGrounded == true` (проверка `Physics2D.OverlapBox` на 0.5 единицы ниже позиции, размер 0.8×0.1).

**Механика:** `rb.velocity.y = 0`, затем `rb.AddForce(Vector2.up * 12f, ForceMode2D.Impulse)`.

**Визуальный feedback:** `DOPunchScale(-0.15y, 0.3x, 0.25сек)` на visual.

### 5.3 Wall Slide

**Условие:** касание стены слева (`_isTouchingLeftWall`) или справа (`_isTouchingRightWall`) + не на земле + `rb.velocity.y < 0`.

**Эффект:** скорость падения ограничена: `rb.velocity.y = max(rb.velocity.y, -2f)`.

**Проверка стен:** `Physics2D.OverlapBox` на 0.5 единицы влево/вправо, размер 0.1×0.8.

### 5.4 Wall Jump

**Условие:** нажата клавиша прыжка + (`_isTouchingLeftWall` или `_isTouchingRightWall`) + `rb.velocity.y <= 0` + не прыгал от этой стены с последнего приземления (`_lastWallJumpDir`).

**Механика:**
- От левой стены: `rb.velocity = 0`, `rb.AddForce(new Vector2(8f, 12f), Impulse)` (вправо-вверх).
- От правой стены: `rb.velocity = 0`, `rb.AddForce(new Vector2(-8f, 12f), Impulse)` (влево-вверх).

**Ограничение:** `_lastWallJumpDir` запоминает направление последнего wall jump. Нельзя прыгнуть дважды от одной стены без промежуточного приземления. Приземление сбрасывает `_lastWallJumpDir = 0`.

### 5.5 Смерть

P2 умирает в трёх сценариях:
1. **KillZone:** триггер под y=0. `OnTriggerEnter2D` / `OnTriggerStay2D` → `character.Die()`.
2. **BombNPC взрыв:** если дистанция до NPC в момент взрыва ≤ `_explodeRadius = 2f` → `character.Die()`.
3. **Прямое раздавливание блоком:** (реализуется через KillZone или физический контакт — зависит от конфигурации коллайдеров в текущей сцене).

**Анимация смерти:** `Animator.SetBool("IsDead", true)`, камера шейкается 0.5 сек / амплитуда 1.0, `Character.enabled = false`, `rb.isKinematic = true`, затем `GameManager.GameOver()`.

## 6. Abilities (способности персонажа с формулами кулдаунов)

### Система кулдаунов

Каждая способность имеет независимый таймер. Таймеры считаются вниз в `Update()`:

```
timer -= Time.deltaTime
```

Способность доступна, когда `timer <= 0`.

Нормализованный прогресс кулдауна (для UI-индикатора):

```
CooldownProgress = 1 - Clamp01(timer / maxCooldown)
```

- `CooldownProgress = 0` → только что использована (полный кулдаун).
- `CooldownProgress = 1` → готова к использованию.

### Ability 1: Destroy Side (X)

| Параметр          | Значение       |
|-------------------|----------------|
| Клавиша           | X              |
| Кулдаун           | 5 секунд       |
| Таймер            | `_destroySideTimer` |
| Анимация          | Trigger "Destroy" |
| Логика            | Animation Event в конце клипа |

**Механика:** при срабатывании (Animation Event `TryDestroySide`):
1. Вычисляется позиция P2 в grid-координатах: `gridPos = RoundToInt(characterPos - boardPos)`.
2. Проверяется клетка спереди: `gridPos + (facingDir, 0)`.
3. Если занята → уничтожается. Кулдаун сбрасывается в 5 сек. Возврат.
4. Если спереди пусто → проверяется клетка сзади: `gridPos + (-facingDir, 0)`.
5. Если занята сзади → уничтожается. Кулдаун сбрасывается. Возврат.
6. Если оба пусты → анимация проигрывается, кулдаун НЕ сбрасывается (способность не "тратится" вхолостую).

**Синхронизация:** `photonView.RPC("RpcDestroyBlock", RpcTarget.All, x, y)`.

### Ability 2: Destroy Down (Z)

| Параметр          | Значение       |
|-------------------|----------------|
| Клавиша           | Z              |
| Кулдаун           | 5 секунд       |
| Таймер            | `_destroyDownTimer` |
| Анимация          | Trigger "DestroyDown" |
| Логика            | Animation Event в конце клипа |

**Механика:** при срабатывании (Animation Event `TryDestroyDown`):
1. Проверяется клетка под ногами: `gridPos + (0, -1)`.
2. Если занята → уничтожается. Кулдаун сбрасывается в 5 сек.
3. Если пусто → кулдаун НЕ сбрасывается.

**Примечание:** `_pendingDestroyDown = true` устанавливается при нажатии клавиши, сбрасывается в Animation Event. Это защита от двойного срабатывания.

**Синхронизация:** `photonView.RPC("RpcDestroyBlock", RpcTarget.All, x, y)`.

### Ability 3: Push (Numpad 0 / Insert)

| Параметр          | Значение       |
|-------------------|----------------|
| Клавиша           | Numpad0 / Insert |
| Кулдаун           | 1 секунда      |
| Таймер            | `_pushTimer`   |
| Анимация          | SetBool "IsPushing" = true, автосброс через 1.2 сек |
| Логика            | Animation Event в конце клипа |

**Механика** (Animation Event `TryPush`):

**Приоритет 1 — BombNPC:**
- Проверяется круг радиуса 0.6 юнита перед персонажем (`characterPos + facingDir * 0.9`).
- Если найден BombNPC → `npc.Push(new Vector2(facingDir, 0.5f))`.
- BombNPC получает импульс: `rb.velocity = 0`, `rb.AddForce(direction.normalized * 8f, Impulse)`.
- Возврат (блок тетриса не проверяется).

**Приоритет 2 — Блок тетриса:**
- Вычисляется `pushPos = gridPos + (facingDir, 0)`.
- `Board.TryPushBlock(pushPos, (facingDir, 0))`.
- Условие успеха: `pushPos` занят И `pushPos + dir` свободен И в границах поля.
- При успехе: блок анимированно перемещается, временно отключается коллайдер.

**Кулдаун сбрасывается независимо от успеха Push.**

**Синхронизация:** `photonView.RPC("RpcPushBlock", RpcTarget.All, px, py, dx, dy)`.

### Таблица кулдаунов

| Способность   | Кулдаун | Taймер (из code) | Категория |
|---------------|---------|------------------|-----------|
| Destroy Side  | 5 сек   | `_destroySideTimer` | Gate   |
| Destroy Down  | 5 сек   | `_destroyDownTimer` | Gate   |
| Push          | 1 сек   | `_pushTimer`        | Gate   |

## 7. Win Conditions (условия победы с edge cases)

### Основная таблица

| Событие | Победитель | Вызов |
|---------|------------|-------|
| P2 достиг Exit (открыт) | P2 | `GameManager.Win()` → `_victoryPanel.ShowP2Wins()` |
| P2 умер (KillZone) | P1 | `GameManager.GameOver()` → `_victoryPanel.ShowP1Wins()` |
| P2 умер (взрыв BombNPC) | P1 | `GameManager.GameOver()` |
| Таймер истёк (3 минуты) | P1 | `GameHUD` → `GameManager.GameOver()` |

После любого исхода: `Time.timeScale = 0f`, `GameHUD.StopTimer()`.

### Edge Cases

**E1: P2 касается Exit в момент его блокировки блоком.**
- Exit проверяет: `OnTriggerEnter2D` → если `exit.IsOpen` → Win. Если блок упал в тот же кадр → зависит от порядка выполнения. Правило: Win проверяется до Lock. Если триггер сработал до Lock — P2 побеждает.

**E2: BombNPC взрывается точно на границе `_explodeRadius = 2f`.**
- Условие: `Vector2.Distance(bombPos, charPos) <= 2f`. При дистанции ровно 2.0f — считается в радиусе, P2 умирает.

**E3: P2 умирает в момент достижения Exit.**
- `GameManager.Win()` и `GameManager.GameOver()` оба проверяют `if (!_isPlaying) return`. Первый вызов устанавливает `_isPlaying = false`. Второй вызов игнорируется. Порядок определяется порядком Update/Trigger в текущем кадре. Правило: Win имеет приоритет — обработчик Exit должен вызываться первым.

**E4: Таймер истёк, P2 одновременно достиг Exit.**
- Аналогично E3. Первый вызов побеждает. Победа Exit должна проверяться до истечения таймера в одном кадре.

**E5: P1 не разместил ни одной фигуры за 3 минуты.**
- Персонаж жив, поле пустое → Exit открыт → P2 побеждает при достижении Exit. Если P2 не дошёл до Exit → таймер истекает → P1 побеждает.

**E6: Переполнение поля (все 20 рядов заняты).**
- Следующая фигура спаунится на y=18. Если клетки заняты → Lock немедленно. P2 оказывается под блоками → смерть через KillZone или физический раздав. Нет отдельного Game Over для P1 от переполнения (в отличие от классического тетриса).

## 8. Exit Mechanic (как работает выход)

### Описание

Exit — объект в сцене с триггер-коллайдером. Позиция задаётся в grid-координатах (`_gridPos`). По умолчанию: `x=0, y=2` (левый нижний угол, вторая строка снизу).

### Состояния

| Состояние | Условие | Визуал |
|-----------|---------|--------|
| Open (открыт) | Клетка `_gridPos` в Board пуста | Зелёный пульсирующий спрайт |
| Blocked (заблокирован) | Клетка `_gridPos` занята блоком | Красный спрайт |

Обновление состояния: Exit опрашивает `Board.IsOccupied(_gridPos)` в каждом кадре (или по событию после Lock/ClearLines).

### Логика победы

```
OnTriggerEnter2D(character):
    if IsOpen:
        GameManager.Instance.Win()
```

P2 должен физически войти в триггер. Достаточно касания (не нужно оставаться внутри).

### Edge Cases Exit

**E7: Exit заблокирован, P2 стоит на нём.**
- Триггер `OnTriggerStay2D` не проверяется (только `OnTriggerEnter2D`). P2 должен выйти и войти снова когда блок исчезнет (очистка линии или Destroy).

**E8: Exit расположен в x=0, y=2 — проблема баланса.**
- Этот угол легко заблокировать с первых ходов. Рекомендуется y ∈ [8, 15] или рандомизация позиции. Текущая позиция — placeholder MVP.

**E9: Блок падает точно в клетку Exit в момент входа P2.**
- Правило то же, что E1. Lock должен проверять Win-триггер до записи в grid. В текущей реализации это не гарантировано — требует ревью порядка вызовов.

## 9. BombNPC (поведение и взаимодействие)

### Спавн

BombNPC появляется в очереди P1 как специальный слот (тип `TetrominoType.Bomb`). P1 выбирает колонку и сбрасывает его аналогично фигуре.

Метод: `TetrisController.SpawnBombNpcAt(gridX)` → `PhotonNetwork.Instantiate("BombNpc", worldPos, ...)`.

**Только MasterClient (P1) управляет физикой и AI BombNPC.**

### Фаза падения (до приземления)

- BombNPC падает под физикой (Rigidbody2D, гравитация).
- При спавне получает начальный импульс `Vector2.up * 4f` (подброс вверх перед падением).
- Ghost-прогноз (оранжевый, alpha 0.45) показывает точку приземления в grid.
- P2 может оттолкнуть BombNPC способностью Push во время падения.
- Приземление определяется через `OnCollisionEnter2D` — нормаль контакта > 0.5 по Y.

### Фаза NPC (после приземления)

**Преследование:**
- `_target` = `GameObject.FindWithTag("Player")`.
- `_moveDir = Sign(target.x - npc.x)`.
- Скорость: `_moveSpeed = 2f` клетки/сек.

**Прыжок через препятствия:**
- Raycast вперёд на `_obstacleCheckDist = 0.6` → если попадает в solid layer → прыгает.
- Кулдаун прыжка: `_jumpCooldown = 0.6` сек.
- Сила прыжка: `_jumpForce = 8f`.

**Задержка перед фитилём:** после приземления 0.5 сек нельзя начать fuse (защита от мгновенного взрыва при спавне рядом с P2).

### Фитиль (Fuse)

| Параметр | Значение |
|----------|---------|
| Расстояние активации | `_explodeDistance = 1f` юнит |
| Время фитиля | `_fuseTime = 2f` секунды |
| Визуал | пульсирующий scale, ускоряется по мере горения |

Формула интервала пульсации:
```
progress = 1 - Clamp01(fuseTimer / fuseTime)
interval = Lerp(0.3, 0.05, progress)
```
Интервал сокращается от 0.3 сек до 0.05 сек по мере сгорания фитиля — нарастающее напряжение.

Пока фитиль горит: BombNPC останавливается (`rb.velocity.x = 0`), не преследует.

### Взрыв

| Параметр | Значение |
|----------|---------|
| Радиус убийства P2 | `_explodeRadius = 2f` юнита |
| Радиус разрушения блоков | 3 клетки (в Board.Explode) |
| Камера | шейк 0.5 сек / амплитуда 1.2 |

`Board.Explode(center, radius=3)`: уничтожает все блоки в круге радиуса 3, проверка `dx^2 + dy^2 <= radius^2`. После взрыва применяется `ApplyGravity()`.

BombNPC уничтожается через `PhotonNetwork.Destroy` (MasterClient).

### Взаимодействие с Push

- Push работает только пока BombNPC не приземлился (`!_isLanded`).
- Импульс: `direction.normalized * _pushForce = 8f`.
- После приземления Push на BombNPC не действует (проверяется в `TryPush` неявно через `_isLanded` — **уточнить в коде: текущая реализация проверяет коллайдер по радиусу 0.6 и компонент BombNPC независимо от `_isLanded`**).

### Edge Cases BombNPC

**E10: P2 толкает BombNPC за пределы поля.**
- BombNPC не ограничен стенами поля (он — отдельный Rigidbody). Может улететь за границу. Если улетает в KillZone — уничтожается. Если уходит за боковую стену — зависит от коллайдеров стен в сцене.

**E11: Несколько BombNPC на поле одновременно.**
- Нет лимита в текущей реализации (автономный spawner был удалён). Лимит определяется только частотой спавна P1.
- Каждый BombNPC независим. Два взрыва в разных местах — складывающийся урон по блокам.

**E12: BombNPC взрывается, когда P2 уже мёртв.**
- `GameManager.GameOver()` уже вызван. Повторный вызов игнорируется (`if (!_isPlaying) return`).

**E13: BombNPC приземляется поверх P2.**
- Оба — физические объекты. Физический контакт не вызывает мгновенную смерть — только взрыв через fuse. P2 имеет 2 секунды убежать после активации фитиля.

### Известные дисбалансы (текущий MVP)

**D1: Exit в (0, 2) — критический дисбаланс.**
Левый нижний угол легко заблокировать с первого хода. P1 может удерживать этот угол без усилий на протяжении всего матча. Требует немедленного изменения при плейтесте.
Решение: y ∈ [10, 15] или рандомизация на старте матча.

**D2: Нет риска для P1 от переполнения поля.**
В классическом тетрисе переполнение = Game Over. Здесь P1 может играть бесконечно без угрозы. Нет стимула торопиться.
Решение (не в MVP): при превышении порогового уровня заполнения (например, y > 15) — P2 получает временный бонус (ускорение, дополнительная способность).

**D3: Wall jump невозможен от одной стены дважды подряд.**
В поздней игре при заполненном поле персонаж может оказаться в коридоре из одной стены — wall jump недоступен, прыжок с земли заблокирован блоком сверху. Ловушка без выхода.
Решение: разрешить второй wall jump от той же стены после определённого времени (например, 0.5 сек).

**D4: Destroy Side и Destroy Down — раздельные кулдауны, но в ранних версиях был общий.**
Текущий код: `_destroySideTimer` и `_destroyDownTimer` — независимые. Это удвоение частоты использования по сравнению с общим кулдауном. Проверить на плейтесте: не слишком ли легко P2.

**D5: Push BombNPC доступен только в воздухе (до приземления).**
При скорости NPC 2 м/сек и дистанции активации fuse 1 м — у P2 ~0.5 сек реакции после приземления NPC. Push после приземления недоступен. P2 должен использовать Z/X для уничтожения пути отступления.

## 11. Session Flow (от старта до конца матча)

### Структура сессии

```
[Lobby / Start Screen]
    |
    | Оба игрока подключились (онлайн) или нажата кнопка Start (LocalDebug)
    v
[Start Panel]
    | StartGame()
    v
[Матч — 3 минуты]
    |
    |--- P1 drag & drops фигуры ----> блоки накапливаются
    |--- P2 бегает, прыгает --------> выживает, ищет Exit
    |--- BombNPC спаунится ---------> угроза для P2
    |
    | Событие победы
    v
[Victory Panel]
    | Restart / Leave Room
    v
[Start Screen / Lobby]
```

### Предматчевая фаза

1. `GameManager.Awake()`: `_startPanel.SetActive(true)`, `_pausePanel.SetActive(false)`, `Time.timeScale = 1f`.
2. Photon: MasterClient → P1 (тетрис). Второй клиент → P2 (персонаж). В LocalDebug один клиент управляет обоими.
3. Нажатие Start: `GameManager.StartGame()` → скрывает StartPanel → запускает таймер → `TetrisController.StartGame()` → если LocalDebug или не MasterClient: `CharacterSpawner.StartGame()`.

### Игровая фаза

- P1 видит NextPiecePreview и поле с ghost piece.
- P2 видит поле с движущимся персонажем и mirror blocks (копии падающей фигуры P1 без управления).
- Pause: клавиша Escape → `TogglePause()` → `Time.timeScale = 0 / 1`.

### Постматчевая фаза

- `_victoryPanel.ShowP1Wins()` / `ShowP2Wins()`.
- `Time.timeScale = 0f`.
- Restart: LocalDebug → перезагрузка сцены. Онлайн → `PhotonNetwork.LeaveRoom()`.

## 12. Out of Scope — MVP

Следующие механики явно исключены из MVP:

| Механика | Причина исключения |
|----------|-------------------|
| Уровни сложности / нарастающая скорость тетриса | `_fallSpeed` не масштабируется с уровнем в текущей реализации |
| Счёт / очки за очищенные линии | Есть переменные, но нет UI-влияния на геймплей |
| Автономный BombNPC Spawner (интервальный) | Удалён (`BombNPCSpawner.cs` удалён в текущей ветке) |
| Несколько Exit / рандомизация позиции Exit | Одна фиксированная позиция |
| Бонусы P2 при высоком заполнении поля | Нет системы |
| Hard Drop (мгновенное падение фигуры) | Только автопадение по скорости |
| Hold piece | Только один слот очереди |
| T-Spin и другие advanced Tetris правила | Нет |
| Звуковые эффекты | Не в scope GDD |
| Matchmaking / рейтинг | Только прямое соединение Photon |
| Мобильные платформы | PC + WebGL только |
| Replay / запись матча | Нет |
| UI кулдаун-индикаторы (Destroy Side/Down/Push) | Есть нормализованные свойства в коде, UI не реализован |

## Приложение B: Acceptance Criteria

### Функциональные критерии

- [ ] P1 может перетащить фигуру в любую валидную колонку.
- [ ] Ghost piece показывает точную позицию приземления.
- [ ] W вращает фигуру на 90° по часовой во время drag.
- [ ] Полная линия (10 клеток) очищается немедленно после Lock.
- [ ] После очистки линии все блоки выше сдвигаются вниз на 1.
- [ ] P2 двигается влево/вправо с мгновенным откликом.
- [ ] P2 прыгает только с земли. Wall jump работает от стены.
- [ ] Wall slide ограничивает скорость падения до -2 ед/сек.
- [ ] Destroy Side уничтожает первый блок перед/за персонажем. Кулдаун 5 сек.
- [ ] Destroy Down уничтожает блок под ногами. Кулдаун 5 сек.
- [ ] Push толкает BombNPC (приоритет) или блок тетриса на 1 клетку. Кулдаун 1 сек.
- [ ] Exit зелёный когда клетка пуста, красный когда занята.
- [ ] Победа P2 при входе в открытый Exit.
- [ ] Победа P1 при смерти персонажа.
- [ ] Таймер 3 минуты считает вниз, по истечении — победа P1.
- [ ] BombNPC преследует персонажа после приземления.
- [ ] BombNPC активирует fuse на дистанции ≤ 1 ед.
- [ ] Взрыв BombNPC убивает P2 в радиусе ≤ 2 ед.
- [ ] Взрыв BombNPC удаляет блоки в радиусе 3 клетки.

### Экспериментальные критерии (плейтест)

- [ ] P1 ощущает смысл каждого хода. Нет "просто бросаю куда попало".
- [ ] P2 имеет хотя бы 1 путь к Exit в первые 60 секунд матча.
- [ ] BombNPC создаёт напряжение, но не убивает немедленно без шанса реакции.
- [ ] Матч не заканчивается менее чем за 30 секунд при нормальной игре.
- [ ] P2 побеждает в ≥ 20% матчей при балансированной игре обеих сторон.
- [ ] Wall jump позволяет подняться на ≥ 5 рядов вертикально в узком коридоре.
- [ ] Push BombNPC ощущается как осмысленный контрмеханизм, не паника-кнопка.
